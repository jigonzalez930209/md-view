# Preview

The right pane renders the document with [markdown-it](https://github.com/markdown-it/markdown-it)
configured like GitHub Flavored Markdown, plus KaTeX and Mermaid.

![Preview of the demo document](/screenshots/split-view.png)

## What it renders

| Feature | Implementation |
| --- | --- |
| Headings, paragraphs, lists, code, quotes | markdown-it core + GFM (tables, strikethrough, autolinks) |
| Task lists `- [x]` | `markdown-it-task-lists`, with disabled checkboxes like GitHub |
| Footnotes `[^1]` | `markdown-it-footnote` |
| Emoji `:rocket:` | `markdown-it-emoji` |
| Alerts `> [!NOTE]` | Custom pass over the rendered HTML (Note, Tip, Important, Warning, Caution) |
| Formulas `$…$`, `$$…$$`, ` ```math ` | KaTeX via `@vscode/markdown-it-katex` |
| Diagrams ` ```mermaid ` | Mermaid, loaded on demand and redrawn when the palette changes |
| Code blocks | highlight.js with 30+ languages and a **copy** button |
| Anchors | Every heading gets its GitHub-style `id` and a link that appears on hover |
| Images, GIF, WebP, AVIF, SVG | Served through the Tauri `asset:` protocol; animated SVGs (SMIL/CSS) work |
| External links | Opened in your browser; local links to another `.md` open in a new tab |

## How relative paths are resolved

Images and links are resolved against the folder of the document you opened:

1. an absolute path (`/assets/x.png`) is tried as-is;
2. if it doesn't exist, it is tried relative to the document folder (typical in READMEs);
3. **if neither exists, the original path is kept as-is**, which is what makes paths served
   by the app itself (like `/demo-animado.svg` in the demo) work.

::: tip Broken images
A reference like `./no-exists.md` simply stays as text; an image that cannot be found keeps
its alt text instead of showing a broken icon.
:::

## View: Markdown or code

Every document has a toggle in the preview header:

- **Markdown** (the default for `.md`, `.mdx`, `.markdown`, `.txt`…): rendered.
- **Code**: the raw source, monospace, with the highlighting of its extension.

For a `.ts` file the code view is the default, so opening source files doesn't turn them
into a single run-on paragraph.

## Synchronized scroll

In split view the two panes stay aligned **by source line**, not proportionally: every block
in the preview carries a `data-line` attribute, so scrolling to a heading in the editor
leaves the same heading on top of the preview, even with images or diagrams in between. The
sync runs once per frame and pauses while you type. It can be turned off in
[Settings](/guide/settings).

## Big documents

The preview adapts to the size of the document instead of freezing:

| Size | What happens |
| --- | --- |
| > 300 KB | Syntax highlighting is turned off |
| > 400 KB | No highlighting and no Mermaid diagrams |
| > 1.5 MB | Only the **first 2,000 lines** are rendered, with a note at the top |
| > 8 MB | The preview is generated by a worker and the DOM is built from the windowed slice |

Rendering runs in a worker for documents over 500 KB, so the interface keeps responding.
Details in [Large documents](/guide/large-documents).

## Security

Everything the Markdown produces goes through sanitization before touching the DOM. If the
document contains no raw HTML, sanitization is skipped (markdown-it already escapes text and
validates link protocols). See [Security](/reference/security).
